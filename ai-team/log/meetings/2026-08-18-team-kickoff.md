# 2026-08-18 AI チーム発足キックオフ

## 概要

CEO「シャチョー」をトップとする 11 名体制の AI チームを発足。体制構築後、PM・テックリード・セキュリティ担当・リリース/DevOps 担当の 4 名を招集し、親フォルダ配下のポートフォリオ初期調査（read-only）と本アプリへの要件出しを実施した。

## オーナーの依頼

- 本アプリ（親フォルダ配下の他プロジェクトの進捗・課題管理、製造・修正・リリース実行を行うアプリ）を動かすためのチームを組む。
- CEO シャチョーがオーナーとの唯一の窓口。メンバーはシャチョーと調整し、結果をシャチョーが報告する。
- 管理対象は固定パスではなく「本リポジトリの親フォルダ」を動的解決（どの PC でも同じ構成なら同じ動作）。

## 検討・実行内容

- 実現方式 3 案から (a) ハイブリッド（cre-ai-team プラグイン＋ローカル増分）をオーナーが選択。
- `.claude/settings.json`（プラグイン有効化）、`CLAUDE.md`（運営規約）、ローカルエージェント 2 体（security-officer / release-ops）、記録の器（ai-team/log/、progress.md、決定台帳）を作成。
- キックオフとして 4 名が親フォルダ配下 6 プロジェクトを read-only 調査。

### メンバー初期所見（要点）

- **[PM]** ポートフォリオ横断の課題は ①ブランチ命名の不統一 ②未コミット/未追跡ファイルの放置（2 プロジェクト）③活動状況の可視化がない ④種別ごとのチェック定義が必要。機能要件候補 F1〜F7 を優先度付きで提示（必須は F1 プロジェクト自動検出・F2 git 状態ダッシュボード）。Phase 分割案: Phase 1=見える化 MVP → Phase 2=課題管理 → Phase 3=実行系。
- **[TL]** 全プロジェクト TypeScript + npm、Next.js + Tailwind 主流。技術スタック推奨は「ローカル Web サーバ + ブラウザ UI（Next.js 15）」、データは当面 JSON ファイル（ネイティブ依存ゼロ）。親フォルダ解決はコード自身の位置基準（`import.meta.url` → `../..`）、git 情報は git CLI の `--porcelain` パース。実行系は「package.json 定義済み scripts のみ実行可」等の安全設計を提示。最重要の未確認事項:「実行」の範囲（本ツールが直接実行するのか、Claude Code を起動する司令塔なのか）。
- **[SEC]** 本アプリは「他プロジェクトを読み書きする権限の大きいツール」であり、それ自体が最大の攻撃対象。最高優先の要件は ①秘密ファイル除外機構（`.env*`・鍵類の deny-list を全経路に）②書き込み・実行の承認ゲート（デフォルト read-only、dry-run → 承認 → 実行）。追跡ファイルへの秘密実体混入は確認されず基本衛生は良好。本リポジトリの .gitignore 未整備を指摘 → 対応済み。
- **[REL]** 全プロジェクトの CI に gitleaks 導入済みは良い土台。既定ブランチ master/main 混在・作業ブランチ名バラバラ・CD 自動化なし（リリース＝/release スキルの手動フローが実態）。リリース実行機能の要件: 明示承認ゲート／/release スキルを正とし二重実装しない／プリフライトチェック／プロジェクト別リリース定義ファイル／監査ログ。環境差分は「コミットする設定＋PC 固有 `*.local`（gitignore）」の二層構成を提案。
